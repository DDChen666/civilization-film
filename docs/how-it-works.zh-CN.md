# 技术说明

这份文档说明这部片的代码怎么组织，给想读代码、或想用同样的方法做自己的片的人。（代码注释是繁体中文。）

## 1. 渲染约定：画面是时间的函数

整部片的核心规则只有一条：**给任何时间 t，都画出完全相同的一帧。**

`stage.html` 对外只提供四样东西：

| 接口 | 作用 |
|---|---|
| `window.__ready` | 一个 Promise。字体、地理数据、配乐时间表加载完成后 resolve |
| `window.__meta` | `{ dur, fps }`，片长与帧率 |
| `window.__seek(t)` | 画出时间 t 的那一帧 |
| `window.__events()` | 切镜的时间，给测量工具用 |

为了遵守这条规则，代码里**不用**定时器、CSS 动画、`Math.random()`，也没有跨帧保存的状态。需要随机数的地方，一律用固定种子的哈希（`E.hash`、`E.rng`）。

遵守它的好处：

- **可以并行输出**：六个浏览器各画一段，最后接起来。
- **可以做真正的动态模糊**：同一帧在快门开启的时间内画好几次，取平均。
- **可以复现**：同一份代码，每次输出都相同。
- **可以实时播放**：`player.html` 只是每一帧用 `audio.currentTime` 调用 `__seek`。

## 2. 输出管线（`render.mjs`）

```
本地静态服务器 ─┬─ Chrome 1：第 0–1489 帧    ─┐
               ├─ Chrome 2：第 1490–2979 帧 ─┼─ 各段 H.264 首尾相接 → ffmpeg 封装、混入配乐（AAC 256k）、标 BT.709 → mp4
               └─ Chrome 3：第 2980–4469 帧 ─┘
每一帧（在页面里）：180° 快门内画 4 个子帧 → 连续平均叠在一张画布上 → VideoFrame → 硬件编码器（WebCodecs → VideoToolbox）
```

- **fast 引擎（默认）**：不截图。画面在页面里叠好动态模糊，直接交给 Mac 的硬件编码器，编好的数据每几 MB 交回 Node 写文件。合成页只有一张画布、画布外没有看得见的元素时自动使用。默认 3 个 Chrome（M3 上最快）。整片 1080p 约 1 分 41 秒。
- **shot 引擎**：旧做法，逐帧截图交给 ffmpeg。画面有网页元素时自动改用这个，也可以用 `--engine shot` 指定。整片约 15 分半。
- 为什么这样做、怎么测出瓶颈、和 HyperFrames 的比较：见[快速输出](fast-render.zh-CN.md)。
- 截图和编码用的是电脑上已安装的 Google Chrome，不另外下载浏览器。
- 色彩空间一定要标成 BT.709，否则 QuickTime 会把颜色洗白。
- 模式：`sheet`（关键帧总览）、`strip`（某一刻前后的连续帧）、`video`（视频）、`events`（导出切镜时间）。

## 3. 世界：真三维、真尺寸

- **坐标**：原点是巴比伦（东经 44.42°、北纬 32.54°）。x 朝东、y 朝北、z 朝上，单位是米。
- **远处的地理放在真实半径的球面上**（`E.makeGeo`）。所以镜头退得够远时，地面会自己弯成地球，不必在两种画法之间切换。
- **只有三种图元**（`src/engine.js`）：
  - `E.line`：线，可以选择被地球挡住（`occlude`）。虚线会先裁到画面里再画（`dashLine`），否则延伸到画面外的长线会拖慢好几十倍
  - `E.face`：实心面，按法线剔除背面，用底色把后面的线挡掉
  - 光点：预先画好的光晕贴图，用加法混合叠上去
- **光晕**：每一层先画在透明图层上，再叠上模糊过的自己（`E.makeLayers`）。
- **整个画面**先画在一张看不见的画布上，再贴到屏幕，这样才能整体套用缩放、震动和闪白。

## 4. 一个镜头（`src/film.js` 的 `KEYS`、`camP1`）

第一部 89 秒只有一个镜头。它的路径写成一张表，每一行是“第几小节：距离、俯角、方位角、画面偏移、视角、目标点”：

```js
//  小节  距离(m)  俯角  方位  偏移x 偏移y 视角 目标
  [0,     0.74,    0,    0,    0,    0,    36,  CP(0, 0, 0.005)],   // 贴着岩壁
  [12,    82,      30,  -27,   40,   130,  36,  CP(14, -30, -1.3)], // 田
  [24.5,  2.6e4,   52,  -30,   170,  70,   36,  [0, 0, 0]],         // 巴比伦上空
  [52,    2.6e7,   89.5, 0,    300, -10,   25,  null],              // 整颗地球
```

- **距离用对数插值**：从 0.74 米到 26,000 公里，跨了 7.5 个数量级。用对数插值，每一小节退的“倍数”才会平均。
- **每一拍往后踢**：拍点上快速后退，拍与拍之间慢慢滑，镜头本身就在打拍子。
- **目标点**是 `null` 时，镜头看向“最近几拍出现的里程碑的重心”（`track`），所以地球会自己转向正在发生事情的地方。
- 俯角变大时，画面的“上”从天空换成北方，避免镜头在头顶翻转。

## 5. 尺度换手（LOD）

同一个镜头，不同距离由不同的场景负责：

| 距离（大约） | 负责的场景 |
|---|---|
| 0.7–500 米 | `scene_land.js`：岩壁与手印（借用 `scene_cave.js`）、营地、田与村子 |
| 0.5–22 公里 | `scene_city.js`：巴比伦 |
| 4 公里以上 | `scene_globe.js`：地球（`earthP1`）。4–22 公里之间和巴比伦叠在一起淡入淡出 |

换手的方式有两种：在重击的闪白下直接切换，或让两张画面叠在一起淡入淡出。地面的点也会按距离换疏密（`groundLOD`），所以一路退都不会看到“地图的边缘”。城外的水渠和村子（`drawLocal`）在巴比伦和地球两个场景都会画，换手时才接得上。

## 6. 里程碑系统（`src/milestones.js`、`src/film.js`）

每一行数据：

```js
// [年份, 繁体名称, 经度, 纬度, 大字, 种类, 简体名称, 英文名称]
[1088, '指南針', 119.45, 32.2, 0, 'i', '指南针', 'The compass'],
```

- **年份**：负数是公元前；比公元前一万年更早的用 `BP(距今几年)`。
- **种类**决定颜色：发明（金）、科学（冰蓝）、建设（骨白）、探索与创造（赭红）。
- **排程**：每一段把它的里程碑排到节拍上。前面几段一拍一件或几拍一件，后面半拍、四分之一拍一件。节拍不变，只有密度在加速。
- **画法**：
  - `ticker`：左边往上滚的清单，最新一行有线连到地球上的地点
  - `drawMarks`：地点放出一圈光，之后留下一盏灯。灯会一直累积，所以到最后整颗地球都是灯
  - `caption`：奇观镜头的大字（年份一行、名称一行）
- **全史重播**（`REROLL`）：176 项在 28 拍里重新滚一次，每一件都在地球上再亮一次。

## 7. 配乐与同步

```
score.py ──→ audio/score.wav
         └─→ data/audio.json ──→ src/film.js（画面）
                              └─→ tools/sync.py（测量）
```

`data/audio.json` 的内容：

| 字段 | 内容 |
|---|---|
| `bpm`、`beats`、`downbeats` | 140、336 个拍点、84 个小节头 |
| `sections` | 10 段的名称与起止时间 |
| `onsets` | 16 种乐器各自的击点时间：`kick`、`snare`、`taiko`、`theme`、`bell`、`impact`、`heart`… |
| `silences` | 4 次静默 |
| `rms`、`low`、`mid`、`high` | 每 10 毫秒的响度与频段能量 |

画面通过 `lib/music.js` 读它：

```js
const mu = Mu.load(audio);
mu.hit('kick', t)        // 最近一次大鼓之后的衰减脉冲（0–1），用来推动光、震动、镜头
mu.events('theme')       // 主题音的时间，里程碑的大字就落在这些点上
mu.beatAt(t)、mu.snap(t) // 第几拍、对齐到最近的拍点
```

段落的重击（`SLAMS`）定义每一段开头的缩放、震动和闪白强度。**代码里没有任何手写的秒数**，所有时间都从 `audio.json` 来。所以改配乐的节奏，画面会自动跟着动。

## 8. 三种语言（`src/i18n.js`）

- 网址参数 `?lang=tc|sc|en`，默认是繁体。
- 代码里写繁体字，`TR()` 查表换成简体或英文。里程碑的三种名称直接写在数据里。
- 字体用 `FontFace` 加载，三种语言各一套开源字体（SIL OFL）。
- 版面按实际字宽排版：英文的段落名是一个词（46px），中文是一个字（76px）。

## 9. 测量工具（`tools/`）

| 工具 | 测什么 |
|---|---|
| `sync.py 成片.mp4 --analysis data/audio.json` | 画面事件和切镜落在拍点上的比例、每拍几个事件、最强重音有没有画面回应、音画时差 |
| `rhythm.py 成片.mp4` | 画面自己的节奏：静止比例、硬切、镜头长度的变化、连击 |
| `check.sh 成片.mp4` | 从成片抽总览图和手机尺寸图，并打印响度、节奏、音画同步 |
| `sections.py audio/score.wav data/audio.json` | 各段的响度和频段占比：“一层层叠上去”有没有真的发生 |

这部片发行版的实测结果：

| 项目 | 数值 | 随机摆放时的期望值 |
|---|---|---|
| 切镜落在拍点上 | 95% | 16% |
| 画面事件落在拍点上 | 78% | 16% |
| 画面事件落在半拍上 | 99% | 31% |
| 最强 10 个重音有画面回应 | 9 个 | — |
| 对上拍点的事件，平均时差 | 4.7 毫秒（标准差 8.9） | — |
| 每拍的画面事件 | 0.43 | — |

## 10. 想用这个方法做自己的片

1. 先写配乐（或先拿到旁白的逐字时间），输出一份时间表。
2. 合成页只读时间表，遵守“画面是时间的函数”。
3. 先用 `node render.mjs sheet --every 0.5` 看关键帧，不要一开始就输出视频。
4. 输出后用 `tools/` 测，不要凭感觉。
5. 每支片的色板、镜头语言、转场都重新决定；可以沿用的是引擎和工具。
