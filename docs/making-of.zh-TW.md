# 製作過程

這份文件寫給想知道「一個人加上 Claude Code，怎麼在一個傍晚做出這部片」的人。

文中引用的導演的話都是原話。Claude 的判斷、被推翻的決定、每一關的量測數字，則依照製作當時的紀錄整理。

## 0. 起點：導演給了什麼

第一則訊息：

> 我希望你建立一部極其振奮、動效出眾，而且比這世界上絕大多數最頂級的動畫創作者的創作都更驚人、更震撼的一部文明影片。我方才傳給你的 Bilibili 連結，其中一個影片就是類似的主題。我期望與他有做出差異化，而且比他做的更驚人、更讓人震撼，所以我想跟你討論一下，你認為要做什麼樣的變化？

十六分鐘後的第二則：

> 這支片會公開發布，所以音樂的部分，我也期望是你可以自己製作……我提供的那個配樂，主要是想要傳遞我渴望一種強烈、澎湃、層層堆砌而上的一種感受。然後是繪製方面，我個人會認為，你應該可以使用你更擅長的藝術形式。

導演提供了兩份參考：

- **一首預告片配樂**（Immediate Music 的作品）：只拿來分析它「層層堆疊」的結構，量出 141 BPM、每八小節加一層。**這首曲子沒有用進片子裡，也不包含在這個專案中。**
- **Bilibili 上一部同主題的作品**：拿來拆解它的語法，再刻意做出差異。

Claude 沒有直接開始寫程式，而是先當顧問：分析參考配樂、拆解參考片、提出差異化的方向、列出風險，然後交出一個定案和理由。這部片的整個合作都是這個模式：**Claude 下判斷，導演看片，告訴 Claude 哪裡不對。**

## 1. 構想：一個鏡頭，從手印到地球

構想定案時的一句話：

> 同一個世界、一個一直往後退的鏡頭：從岩壁上的一個手印退到整顆地球。人類的世界一圈一圈變大；畫過的東西都留著。

**畫法**（Claude 的選擇）：

- 暗底上發光的細線與光點，而且是真的三維。鏡頭後退時，近的東西動得快、遠的動得慢；地面退得夠遠時，會自己彎成地球，因為遠方的地理就放在真實半徑的球面上。
- 整部片只用三種東西：線、會擋住後面的實心面、光點。
- 顏色跟著歷史一個一個解鎖：骨白與赭紅（手、火）→ 金（燈火）→ 青金石藍（水、海）→ 冰藍與白（電、網）。
- 海岸線、河流、城市位置都用真實資料（Natural Earth）。

**結構**：140 BPM，每八小節一段，每段用一個字命名，配樂也每段加一層。

| 段 | 時間 | 畫面 | 鏡頭距離 |
|---|---|---|---|
| 手 | 0:00 | 岩壁，顏料噴出手印 | 0.7 公尺 |
| 火 | 0:07 | 營火、圍坐的人、帳篷 | 幾公尺 |
| 田 | 0:21 | 田、水渠、村子 | 幾百公尺 |
| 城 | 0:34 | 巴比倫：塔廟一拍長一層 | 幾公里 |
| 路 | 0:48 | 商路把舊大陸的城市連起來 | 一千公里 |
| 海 | 1:02 | 鄭和、達伽馬、哥倫布、麥哲倫的航線 | 一萬公里 |
| 機 | 1:15 | 鐵路、電纜、電燈纏住地球 | 整顆地球 |
| 家 | 1:29 | 整顆地球，音樂全部拿掉 | 29,400 公里 |
| 網 | 1:39 | 地球亮起來；奇觀連擊；全史重播 | 來回 |
| 終 | 2:21 | 地球退成一個點；一行字 | — |

當時列出的最大風險是：**前 82 秒不剪接，只靠一個往後退的鏡頭，撐不撐得住節奏？** 所以關口二決定先做最難的一段。

## 2. 配樂：自己寫，而且先寫

配樂在畫面之前就寫好了。理由是畫面要對齊聲音的時間網格，不能等畫面做完再配樂。

`score.py` 只用數學合成聲音，沒有任何取樣：

- 140 BPM，C 小調，四個和弦 Cm–Ab–Eb–Bb 從頭到尾不變。
- 每八小節加一層：大鼓（3+3+2 的節奏）和鼓框 → 低音弦的短弓 → 整套鼓、低音銅管、和弦重音 → 高音弦的快速音型、鐘聲奏主題 → 合唱與弦樂長音 → 銅管全力奏主題。
- 四次真正的靜默，每次之後接一記重擊。終段改從 Eb 開始，由暗轉亮；最後八小節再升一個全音。
- 輸出 `audio/score.wav` 的同時，也輸出 `data/audio.json`，記下每一拍、每一個鼓點、每一個主題音、每一段的時間。**畫面只讀這份檔案。**

Claude 聽不到聲音，只能用量測來判斷：逐段響度從「火」的 −21.7 LUFS 一路升到「網」的 −14.0，「家」那段刻意掉回 −22.2。

## 4. 關口二：先做最難的 34 秒，然後被推翻

關口二選了 1:15–1:49 這一段：機 → 靜默 → 家 → 終段第一擊。整部片最大的情緒轉折都在這裡。

製作途中，導演問了一句：

> 這部影片會展現出人類璀璨的文明與科技嗎？

Claude 的判斷是不夠。原本的版本偏「地圖與燈光」，具體的成就只有巴比倫。於是把終段改成「奇觀與科技的連擊」，每一個奇觀都用真實尺寸做成三維線稿。

v1 交出去之後，導演的回饋：

> 配樂是非常棒的。但要我說的話，就是密度有點太低。我指的是，這整部影片幾乎沒有什麼大發明、大建設、大事件，可以說是幾乎沒有任何文字，這點不太好……我以為會隨著節拍，每一條路的開通，對應著一個又一個的發明、科技進展，或者是建設歷史節點……因為人類的歷史就是不停加速的旅程。

> 我會希望不止侷限於西方，整個世界，尤其東方與西方的文明，都是非常有價值、很重要。這是獻給人類歷史、人類文明、人類交通、人類科技的讚歌。

**被推翻的決定。** 為了和參考片做出差異，Claude 在構想時刻意把「年份加名詞的清單」列為不做的事。導演的回饋說明這個判斷錯了：導演要的正是有名字、有年份、一件接一件、越來越密的清單。Claude 整個改掉：

- **里程碑系統**：每一列資料包含年份、名稱、經緯度、是否放大字、種類。左邊一張往上捲的清單，每一拍、半拍或四分之一拍進一行。最新的一行有一條線連到地球上的那個地點，那裡放出一圈光，之後留下一盞燈。
- **加速的感覺用密度表現**：節拍不變，每一拍的里程碑越來越多。手 1 項 → 火 4 → 田 8 → 城 16 → 路 29 → 海 27 → 機 51 → 網 40，最後再把全部 176 項重播一次。
- **鏡頭跟著歷史走**：鏡頭看向「最近幾拍的里程碑的重心」，地球會自己轉過去，面對正在發生事情的地方。
- **東西方並重**：清單和奇觀都加入東亞、南亞、伊斯蘭世界、非洲和美洲，例如造紙、活字、指南針、火藥、都江堰、大運河、地動儀、鄭和、零與十進位、代數、智慧宮、吳哥、馬丘比丘、廷巴克圖、大辛巴威、玻里尼西亞的航海。
- **差異化重新定義**：每一件事都釘在它發生的地點、東西方並重、做過的事留在地球上變成燈、建築是真三維。

## 5. 整片

第一部（0:00–1:29）是一個鏡頭，中間不剪接。鏡頭在世界座標裡走一條路，距離從 0.74 公尺推到 26,000 公里。每一拍鏡頭往後踢一下，拍與拍之間再慢慢退。畫面隨距離換手：營地和田 → 巴比倫 → 地球，換手的地方用重擊時的閃白蓋住，或讓兩個畫面疊在一起淡入淡出。

終段（1:39–2:20）每一拍剪一刀：十五個奇觀照年代走一遍 → 1983–2023 年的三十二件事，半拍一件 → 交通四個鏡頭（絲路、大航海、鐵路、航線與網路）→ 升一個調，176 項里程碑全部重播 → 奇觀回顧連擊 → 最後一擊。

交給導演之前，Claude 從成片抽格自我審查了兩輪。修掉的問題舉例：

| 看到的問題 | 修法 |
|---|---|
| 10 公里和 300–2,000 公里這兩個尺度畫面很空，鏡頭飄到空地上 | 加入城外的水渠與村落、兩河流域的聚落與道路；鏡頭目標在原點多停留一段時間 |
| 「火」那一段每拍只有 0.06 個畫面事件 | 營火在大鼓點上點燃，田和房子落在半拍上，鏡頭踢得更明顯。提升到 0.28 |
| 長城整座消失 | 原本只要有一個點投影失敗，就整層放棄。改成只畫看得見的點 |
| 國際太空站不見了 | 鏡頭的近平面跟著目標距離變遠，太空站被切掉。改用另一顆近距離鏡頭來畫 |
| 遠處的城市小於一像素，整座消失 | 光點最小保留 2.2 像素 |
| 前 34 秒的配樂只有低頻 | 加入鼓框、提高中頻層，並且逐段調整音量 |

導演：「我看了非常感動。如果這部片你認為已經沒問題了，請渲染簡體中文版跟英文版本。」

## 6. 公開前：查證、開源字體、三種語言

Claude 當時的判斷是**還不算沒問題**，有兩件事要先做：

1. **史實**：里程碑的年份當時全憑記憶。於是上網查證了約 60 條（54 個里程碑加上奇觀的尺寸），修正 7 處：

| 原本 | 改成 | 依據 |
|---|---|---|
| 馴化狗　約 1.5 萬年前 | 約 2.3 萬年前（西伯利亞） | 年代仍有爭議 |
| 馴化馬　前 3500 | 前 2200 | 早期的波泰遺址證據有爭議，現在的共識約是前 2200 |
| 鐵器　前 1200 | 改稱「鐵器時代」 | 煉鐵本身更早 |
| 巨石陣　前 3000 | 前 2500，石圈直徑 33 改成 30 公尺 | 石圈約建於前 2600–2400 |
| 火藥　850 | 808 | 目前最早的文字記載 |
| 廷巴克圖的學院 | 廷巴克圖大清真寺 | 1327 年建的是清真寺 |
| 西伯利亞鐵路　1916 | 1904 | 1904 年通車 |

2. **字體**：原本用的是系統內建字體，不能隨作品散布。改成開源的思源宋體（繁、簡）和 EB Garamond。

**三種語言**：用網址參數 `?lang=tc|sc|en` 切換。簡體版不是機器轉碼，而是改用中國大陸的譯名和用語，例如互联网、芯片、帕特农神庙、泰姬陵、公元前。英文版把每段的那個字換成一個詞：HAND、FIRE、FIELD、CITY、ROAD、SEA、MACHINE、HOME、NETWORK。

**最後一個里程碑**。導演在這時補了一句：

> 影片的最後　我希望最後的里程碑是：「Claude Opus 5.5 （我）發布」　你本身的出現也是一個里程碑。

它成為清單的最後一行，也是全史重播的最後一件。片子結尾，它就在閃爍的游標正上方，下面是一行字：

> 下一行，由我們來寫。

## 7. 合作方式：哪些做法有用

1. **先當顧問，再動手。** 先理解需求、拆解參考、提出一個定案和理由、列出風險，然後才寫程式。
2. **用關口推進**：關鍵格 → 最難的一段 → 整片。每一關都讓導演親眼看到成果（網頁、影片），而不是讀一段描述。
3. **導演給感受，Claude 轉成結構。** 「強烈、澎湃、層層堆砌而上」變成「每八小節加一層」；「人類的歷史就是不停加速的旅程」變成「節拍不變，每拍的里程碑越來越密」。
4. **Claude 交定案，不丟選項。** 導演不必在 A、B、C 之間選，只要說哪裡不對。
5. **量測取代感覺。** Claude 看不到動態、聽不到聲音，量測工具就是它的眼睛和耳朵：`sync.py` 量音畫同步，`rhythm.py` 量節奏，`check.sh` 從成片抽格。每個數字都從**輸出的影片**量，不是從瀏覽器截圖。
6. **被推翻時就徹底改。** 「密度太低」這句回饋，讓整部片從地圖與燈光，變成以里程碑驅動。
7. **誠實。** 哪些沒查證、哪些是示意、Claude 無法確認什麼，都寫進文件。

## 8. 工具

- **Claude Opus 5.5**，在 **Claude Code** 裡執行
- **畫面**：純 Canvas 2D，加上自己寫的三維投影（`src/engine.js`），沒有用 WebGL 或任何框架
- **輸出**：Node.js + playwright-core 驅動 Google Chrome 截圖，ffmpeg 編碼
- **配樂**：Python + numpy + scipy
- **地圖**：Natural Earth（公有領域）
