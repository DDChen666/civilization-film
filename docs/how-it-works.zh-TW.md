# 技術說明

這份文件說明這部片的程式怎麼組織，給想讀程式碼、或想用同樣的方法做自己的片的人。

## 1. 渲染合約：畫面是時間的函式

整部片的核心規則只有一條：**給任何時間 t，都畫出完全相同的一格。**

`stage.html` 對外只提供四樣東西：

| 介面 | 作用 |
|---|---|
| `window.__ready` | 一個 Promise。字體、地理資料、配樂時間表載入完成後 resolve |
| `window.__meta` | `{ dur, fps }`，片長與影格率 |
| `window.__seek(t)` | 畫出時間 t 的那一格 |
| `window.__events()` | 切鏡的時間，給量測工具用 |

為了遵守這條規則，程式裡**不用**計時器、CSS 動畫、`Math.random()`，也沒有跨格保存的狀態。需要亂數的地方，一律用固定種子的雜湊（`E.hash`、`E.rng`）。

遵守它的好處：

- **可以平行輸出**：六個瀏覽器各畫一段，最後接起來。
- **可以做真正的動態模糊**：同一格在快門開啟的時間內畫好幾次，取平均。
- **可以重現**：同一份程式，每次輸出都相同。
- **可以即時播放**：`player.html` 只是每一格用 `audio.currentTime` 呼叫 `__seek`。

## 2. 輸出管線（`render.mjs`）

```
本機靜態伺服器 ─┬─ Chrome 1：第 0–744 格   ─┐
               ├─ Chrome 2：第 745–1489 格 ─┤
               ├─ …                         ├─ ffmpeg concat → 標上 BT.709 → 混入配樂（AAC 256k）→ mp4
               └─ Chrome 6：…               ─┘
每一格：在 180° 快門內取 4 個子格 → ffmpeg tmix 平均 → 一格有動態模糊的畫面
```

- 截圖用 playwright-core 驅動電腦上已安裝的 Google Chrome，不另外下載瀏覽器。
- 色彩空間一定要標成 BT.709，否則 QuickTime 會把顏色洗白。
- 模式：`sheet`（關鍵格總覽）、`strip`（某一刻前後的連續格）、`video`（影片）、`events`（匯出切鏡時間）。

## 3. 世界：真三維、真尺寸

- **座標**：原點是巴比倫（東經 44.42°、北緯 32.54°）。x 朝東、y 朝北、z 朝上，單位是公尺。
- **遠處的地理放在真實半徑的球面上**（`E.makeGeo`）。所以鏡頭退得夠遠時，地面會自己彎成地球，不必在兩種畫法之間切換。
- **只有三種圖元**（`src/engine.js`）：
  - `E.line`：線，可以選擇被地球擋住（`occlude`）
  - `E.face`：實心面，依法線剔除背面，用底色把後面的線擋掉
  - 光點：預先畫好的光暈貼圖，用加法混合疊上去
- **光暈**：每一層先畫在透明圖層上，再疊上模糊過的自己（`E.makeLayers`）。
- **整個畫面**先畫在一張看不見的畫布上，再貼到螢幕，這樣才能整體套用縮放、震動和閃白。

## 4. 一個鏡頭（`src/film.js` 的 `KEYS`、`camP1`）

第一部 89 秒只有一個鏡頭。它的路徑寫成一張表，每一列是「第幾小節：距離、俯角、方位角、畫面偏移、視角、目標點」：

```js
//  小節  距離(m)  俯角  方位  偏移x 偏移y 視角 目標
  [0,     0.74,    0,    0,    0,    0,    36,  CP(0, 0, 0.005)],   // 貼著岩壁
  [12,    82,      30,  -27,   40,   130,  36,  CP(14, -30, -1.3)], // 田
  [24.5,  2.6e4,   52,  -30,   170,  70,   36,  [0, 0, 0]],         // 巴比倫上空
  [52,    2.6e7,   89.5, 0,    300, -10,   25,  null],              // 整顆地球
```

- **距離用對數內插**：從 0.74 公尺到 26,000 公里，跨了 7.5 個數量級。用對數內插，每一小節退的「倍數」才會平均。
- **每一拍往後踢**：拍點上快速後退，拍與拍之間慢慢滑，鏡頭本身就在打拍子。
- **目標點**是 `null` 時，鏡頭看向「最近幾拍出現的里程碑的重心」（`track`），所以地球會自己轉向正在發生事情的地方。
- 俯角變大時，畫面的「上」從天空換成北方，避免鏡頭在頭頂翻轉。

## 5. 尺度換手（LOD）

同一個鏡頭，不同距離由不同的場景負責：

| 距離（大約） | 負責的場景 |
|---|---|
| 0.7–500 公尺 | `scene_land.js`：岩壁與手印（借用 `scene_cave.js`）、營地、田與村子 |
| 0.5–22 公里 | `scene_city.js`：巴比倫 |
| 4 公里以上 | `scene_globe.js`：地球（`earthP1`）。4–22 公里之間和巴比倫疊在一起淡入淡出 |

換手的方式有兩種：在重擊的閃白下直接切換，或讓兩張畫面疊在一起淡入淡出。地面的點也會依距離換疏密（`groundLOD`），所以一路退都不會看到「地圖的邊緣」。城外的水渠和村子（`drawLocal`）在巴比倫和地球兩個場景都會畫，換手時才接得上。

## 6. 里程碑系統（`src/milestones.js`、`src/film.js`）

每一列資料：

```js
// [年份, 繁體名稱, 經度, 緯度, 大字, 種類, 簡體名稱, 英文名稱]
[1088, '指南針', 119.45, 32.2, 0, 'i', '指南针', 'The compass'],
```

- **年份**：負數是西元前；比西元前一萬年更早的用 `BP(距今幾年)`。
- **種類**決定顏色：發明（金）、科學（冰藍）、建設（骨白）、探索與創造（赭紅）。
- **排程**：每一段把它的里程碑排到拍子上。前面幾段一拍一件或幾拍一件，後面半拍、四分之一拍一件。節拍不變，只有密度在加速。
- **畫法**：
  - `ticker`：左邊往上捲的清單，最新一行有線連到地球上的地點
  - `drawMarks`：地點放出一圈光，之後留下一盞燈。燈會一直累積，所以到最後整顆地球都是燈
  - `caption`：奇觀鏡頭的大字（年份一行、名稱一行）
- **全史重播**（`REROLL`）：176 項在 28 拍裡重新捲一次，每一件都在地球上再亮一次。

## 7. 配樂與同步

```
score.py ──→ audio/score.wav
         └─→ data/audio.json ──→ src/film.js（畫面）
                              └─→ tools/sync.py（量測）
```

`data/audio.json` 的內容：

| 欄位 | 內容 |
|---|---|
| `bpm`、`beats`、`downbeats` | 140、336 個拍點、84 個小節頭 |
| `sections` | 10 段的名稱與起訖時間 |
| `onsets` | 16 種樂器各自的擊點時間：`kick`、`snare`、`taiko`、`theme`、`bell`、`impact`、`heart`… |
| `silences` | 4 次靜默 |
| `rms`、`low`、`mid`、`high` | 每 10 毫秒的響度與頻段能量 |

畫面透過 `lib/music.js` 讀它：

```js
const mu = Mu.load(audio);
mu.hit('kick', t)        // 最近一次大鼓之後的衰減脈衝（0–1），拿來推動光、震動、鏡頭
mu.events('theme')       // 主題音的時間，里程碑的大字就落在這些點上
mu.beatAt(t)、mu.snap(t) // 第幾拍、對齊到最近的拍點
```

段落的重擊（`SLAMS`）定義每一段開頭的縮放、震動和閃白強度。**程式裡沒有任何手寫的秒數**，所有時間都從 `audio.json` 來。所以改配樂的節奏，畫面會自動跟著動。

## 8. 三種語言（`src/i18n.js`）

- 網址參數 `?lang=tc|sc|en`，預設是繁體。
- 程式裡寫繁體字，`TR()` 查表換成簡體或英文。里程碑的三種名稱直接寫在資料裡。
- 字體用 `FontFace` 載入，三種語言各一套開源字體（SIL OFL）。
- 版面依實際字寬排版：英文的段落名是一個詞（46px），中文是一個字（76px）。

## 9. 量測工具（`tools/`）

| 工具 | 量什麼 |
|---|---|
| `sync.py 成片.mp4 --analysis data/audio.json` | 畫面事件和切鏡落在拍點上的比例、每拍幾個事件、最強重音有沒有畫面回應、音畫時差 |
| `rhythm.py 成片.mp4` | 畫面自己的節奏：靜止比例、硬切、鏡頭長度的變化、連擊 |
| `check.sh 成片.mp4` | 從成片抽總覽圖和手機尺寸圖，並印出響度、節奏、音畫同步 |
| `sections.py audio/score.wav data/audio.json` | 各段的響度和頻段佔比：「一層層疊上去」有沒有真的發生 |

這部片發行版的實測結果：

| 項目 | 數值 | 隨機擺放時的期望值 |
|---|---|---|
| 切鏡落在拍點上 | 95% | 16% |
| 畫面事件落在拍點上 | 78% | 16% |
| 畫面事件落在半拍上 | 99% | 31% |
| 最強 10 個重音有畫面回應 | 9 個 | — |
| 對上拍點的事件，平均時差 | 4.7 毫秒（標準差 8.9） | — |
| 每拍的畫面事件 | 0.43 | — |

## 10. 想用這個方法做自己的片

1. 先寫配樂（或先拿到旁白的逐字時間），輸出一份時間表。
2. 合成頁只讀時間表，遵守「畫面是時間的函式」。
3. 先用 `node render.mjs sheet --every 0.5` 看關鍵格，不要一開始就輸出影片。
4. 輸出後用 `tools/` 量，不要憑感覺。
5. 每支片的色板、鏡頭語言、轉場都重新決定；可以沿用的是引擎和工具。
